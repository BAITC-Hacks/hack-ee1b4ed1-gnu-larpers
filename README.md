# Граф денег — Python-анализ

Python-анализ и отдельный React-интерфейс для кейса «Граф денег». Читает три Parquet-файла, проверяет согласованность, определяет наблюдаемые роли клиентов, выделяет группы и формирует CSV для сдачи и JSON для интерфейса. Аналитика работает без серверного API и LLM; фронтенд читает готовые результаты.

Реализация создана отдельно от фронтенда, по предоставленным README, схеме данных и стартовому Python-коду. Полное ТЗ в исходных материалах отсутствовало. Результат — объяснимый эвристический baseline, без заявлений о доказанном мошенничестве или измеренной точности классификации.

## Запуск

Нужны Python 3.11–3.14 и uv. Точные версии зависимостей закреплены в `uv.lock`.

```bash
uv sync --locked
uv run --frozen money-graph --data data --out out
```

В каталоге `data` должны лежать `nodes.parquet`, `edges.parquet` и `transactions.parquet` из предоставленного архива. Данные и результаты исключены из Git. Код ничего не отправляет во внешние сервисы.

Другие способы запуска после установки окружения:

```bash
.venv/bin/python -m money_graph --data data --out out
.venv/bin/python starter.py --data data --out out
```

Параметры: `--top 50` (минимум 20), `--window-days 3` (1–30), `--seed 42`, `--resolution 1.0`. Для набора меньше 20 узлов экспортируются все узлы. Ошибка входных данных завершает команду с кодом 1 и понятным сообщением.

## Локальный фронтенд

Отдельный интерфейс находится в `frontend/` и использует React, TypeScript, Vite и Cytoscape. Он создан независимо от main и не меняет Python-методику. Нужен Node.js 22.12+ либо 24+.

```bash
cd frontend
npm ci
npm start
```

`npm start` сначала запускает Python-анализ и записывает выгрузки в `frontend/public/generated`, затем открывает dev-сервер на **http://127.0.0.1:5174**. Уже подготовленные данные можно открыть через `npm run dev`.

В интерфейсе доступны поиск по всем 2 248 клиентам, фильтры ролей и групп, граф на 1–2 шага и обзор всей сети, выбор узла мышью, основания роли, динамика по активным дням, таблица переводов с датами и направлениями, группы и скачивание CSV/JSON. ID сохраняются строками. Большие окружения ограничиваются 250 узлами с явным счётчиком; обзор показывает все узлы выбранной группы или всего графа. Даты фильтруют таблицу переводов, не пересчитывая месячные роли и приоритеты.

```bash
npm run check
npm run build
```

Сборка также пересчитывает Python-данные. Готовый сайт находится в `frontend/dist`; автоматически публиковать его с банковскими данными не нужно. `node_modules`, `dist` и `public/generated` исключены из Git. Данные не отправляются внешним сервисам.

## Результаты

| Файл | Содержание |
|---|---|
| `nodes_roles.csv` | Все входные клиенты, включая изоляты; роль, обоснованность, кластер, приоритет и объяснение до 200 символов |
| `clusters.csv` | Группы, число клиентов/seed, внутренние и внешние потоки, ведущие узлы и структурная гипотеза |
| `top_nodes.csv` | Ранжированный список; по умолчанию 50 клиентов |
| `graph.json` | Узлы, рёбра, группы, топ, дневные потоки, исходные транзакции и метаданные |
| `summary.json` | Количества, параметры, методы, ограничения, SHA-256 нормализованных данных |
| `report.md` | Краткий читаемый отчёт с первыми десятью узлами |

Обязательные поля стартера сохранены. Дополнительные признаки описаны в `docs/methodology.md`. Неопределимое отношение исходящих к входящим записывается как `unavailable` в CSV и `null` в JSON, с отдельным `pass_through_available=false`. Аналогично экспортируется временная доля без входящих. Пустых ячеек CSV нет. Это явная договорённость нашего экспорта, которую нужно сверить с полным ТЗ, если оно требует конкретное числовое представление отсутствующих значений.

### Контракт для фронтенда

- `schema_version=1` находится в `metadata`.
- **Все `gid`, `src`, `dst` в JSON — строки.** Исходные int64 больше безопасного диапазона JavaScript. `top_gids` — массив строк; в CSV это строка с `;` между ID.
- Денежные значения `*_minor` — целые тиыны; `*_kzt` — значения для отображения. Общий объём проверяется на безопасный диапазон JSON-чисел.
- `date` — `YYYY-MM-DD`. Времени внутри дня нет.
- `role_score` — эвристическая поддержка роли, `priority_score` — приоритет исследования. Оба в диапазоне 0–1 и не являются вероятностями мошенничества.
- У `terminal` проверяйте `role_status` и `truncated_by_depth`: `boundary_hypothesis` означает неподтверждённую конечную роль на границе обхода.
- `flags` — массив пометок; во всех узлах есть `partial_observation`.
- Для построения графа используйте строковые ID напрямую. Не преобразуйте их через `Number()`.

## Проверка предоставленного датасета

Локальный запуск подтвердил 2 248 клиентов, 3 119 рёбер, 4 840 транзакций и сумму по рёбрам 365 890 012,01 ₸ за 1–31 июля 2026 года. Это оборот по наблюдаемым переводам: одна и та же сумма может учитываться на нескольких шагах цепочки.

Сохранены 19 изолированных seed-клиентов и 97 повторных строк транзакций. Без transaction ID эти строки нельзя автоматически считать ошибочными дублями. Все 444 клиента четвёртого колена помечены как граница наблюдения. Суммы и количества переводов по каждой направленной паре совпадают с `edges.parquet`.

При параметрах по умолчанию получены 67 групп Louvain, включая одноузловые группы, и топ-50. Это результат выбранной эвристики кластеризации, а не установленное число экономических организаций.

## Проверки разработки

```bash
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv run --frozen pytest -q
```

Тесты проверяют согласованность входа, целые тиыны, большие ID, сохранение повторных транзакций и изолятов, границу глубины, ограничения seed, направление потоков, отсутствие двойного учёта во временном сопоставлении, самопереводы, CLI и побайтовый детерминизм экспортов при перестановке входных строк.

## Структура

- `money_graph/dataset.py` — загрузка, нормализация и проверки.
- `money_graph/temporal.py` — дневные потоки и сопоставление объёмов.
- `money_graph/analysis.py` — граф, признаки, группы, ранжирование.
- `money_graph/roles.py` — правила ролей и объяснения.
- `money_graph/export.py` — проверка результатов и CSV/JSON/Markdown.
- `money_graph/cli.py` — командный интерфейс.

Фронтенд подключён к `graph.json`. Следующий этап — сверить экспорт с полным ТЗ и провести экспертную проверку ролей. Дополнительное обучение модели потребует размеченных ролей или экспертной проверки; текущие данные такой разметки не содержат.
